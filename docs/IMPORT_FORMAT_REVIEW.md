# FinanceIQ — разбор выгрузки Money Manager

**Статус:** исходный образец рассмотрен; профиль money_manager_xlsx_v1 и синтетический пример приняты 2026-10-30, пункт 0.7 завершен.

**Дата:** 2026-10-30.

Пользователь подтвердил источник: мобильное приложение Money Manager, в котором расходы и доходы вносятся вручную. Изучена структура предоставленного XLSX. Реальные даты, суммы, названия счетов и категории из файла в этот документ не перенесены.

2026-10-30 пользователь согласовал Money Manager XLSX как единственный первоначальный формат импорта вместо банковского CSV. Дополнительно он подтвердил: записи относятся только к состоявшимся движениям, `Дата и время` означает день внесения записи в приложение, и запись всегда вносится в день движения денег. В описанном пользователем процессе эти даты совпадают; банковскую дату проведения файл не подтверждает.

Согласованы импорт книги целиком, явное сопоставление существующим собственным счетам FinanceIQ без автосоздания и календарь источника `Europe/Saratov` (UTC+4). Для импортируемых данных пользователь согласовал сохранение исходной покупки и отдельную запись возврата на дату движения денег. Прежний способ редактирования старой записи не применяется к данным, подготавливаемым для FinanceIQ.

Связанные документы: [PRODUCT.md](PRODUCT.md), [DECISIONS.md](DECISIONS.md), [ROADMAP.md](ROADMAP.md).

## 1. Что подтверждено образцом

Книга содержит листы `Расходы`, `Доходы` и `Переводы`. Первая строка каждого листа — заголовок отчета, вторая — названия колонок; записи начинаются с третьей строки. Лист переводов содержит только заголовки: поведение непустых переводов по этому образцу проверить нельзя.

Листы `Расходы` и `Доходы` имеют одинаковые колонки:

| Колонка | Наблюдение и значение для проектирования |
| --- | --- |
| `Дата и время` | Числовая дата Excel. Дата внесения совпадает с днем операции по подтверждению пользователя; календарь источника — Europe/Saratov. В рассмотренных записях дробной части суток нет |
| `Категория` | Категория из ручного журнала; не банковский тип операции и не идентификатор категории FinanceIQ |
| `Счет` | Текстовое обозначение счета источника; не серверный идентификатор FinanceIQ и не доказательство принадлежности счета |
| `Сумма в валюте счета` | Числовая величина. В рассмотренных записях обоих листов положительная; направление нельзя получить только из знака |
| `Валюта счета` | В образце `RUB` |
| `Сумма операции в валюте операции` | В исходных записях пусто; профиль допускает пустую пару с валютой либо точную RUB-величину, равную сумме в валюте счета |
| `Валюта операции` | В исходных записях пусто; полная пара по профилю требует RUB, валютная конвертация не добавляется |
| `Теги` | В исходных записях пусто; принятый профиль сохраняет исходный текст без угадывания разделителей и создания системы тегов |
| `Комментарий` | В исходных записях пусто; принятый профиль переносит комментарий в описание, пустое значение остается пустым |

Лист `Переводы` имеет отдельную структуру:

1. `Дата и время`.
2. `Исходящий счет`.
3. `Входящий счет`.
4. `Сумма в исходящей валюте счета`.
5. `Валюта исходящего счета`.
6. `Сумма во входящей валюте счета`.
7. `Валюта входящего счета`.
8. `Комментарий`.

Колонок статуса, банковского ID, отдельной банковской даты проведения и отдельной комиссии в этих структурах нет. Формул в рассмотренных записях нет. Эти наблюдения относятся к предоставленной книге, а не ко всем версиям Money Manager.

## 2. Последствия выбора источника

| Основание | Последствие |
| --- | --- |
| Money Manager XLSX выбран вместо банковского CSV, `PRODUCT.md`, §6 | Поддерживается один источник. У XLSX нет CSV-разделителя или CSV-кодировки; промежуточная конвертация в CSV для MVP не требуется |
| Пользовательская дата occurred_on, D-07 | День записи совпадает с днем движения по подтверждению пользователя; банковское проведение не приписывается. Правила локальной даты приняты в профиле |
| Проведенные операции и банковские статусы, D-05/D-08 | Статусов нет. Отсутствие статуса не доказывает проведение, отсутствие отмен или отсутствие плановых записей |
| Положительное поступление, отрицательное списание, D-01 | Положительные величины расходов/доходов преобразуются по листу; отрицательные исходные значения не исправляются через abs. Правила сумм приняты в профиле |
| Отдельные реальные стороны и подтверждение собственного перевода, D-04 | Одна строка переводов содержит два счета. Она сама по себе не подтверждает два банковских движения, даты их проведения или пользовательское подтверждение по правилам FinanceIQ |
| Импорт книги целиком с сопоставлением счетов согласован | Все используемые счета источника явно сопоставляются существующим собственным счетам FinanceIQ, включая оба счета перевода; автоматического создания счетов нет |
| Остатки и полнота по выписке, D-06 | Ручной журнал сам по себе не подтверждает банковский остаток или полноту истории. Название периода отчета не заменяет подтверждения пользователя |

Названия листов и категорий не дают оснований автоматически считать все поступления доходами, а все списания расходами: экономический смысл подтверждается по D-04/D-05 и принятому профилю; одно имя листа не заменяет эту проверку.

## 3. Принятый контракт

**Согласовано 2026-10-30:** полный профиль [money_manager_xlsx_v1](IMPORT_FORMAT.md) и его синтетический образец приняты пользователем. Банковский CSV вне MVP; пункт 0.7 завершен как задача проектирования.

Контракт закрепляет точную структуру трех листов, числовые даты/суммы, положительные исходные RUB-величины и направление по листу/стороне, пользовательскую occurred_on в Europe/Saratov, сохранение реквизитов источника и комментария, отдельный refund и две стороны полной записи перевода с явным подтверждением.

Идентичность/повторы (0.8), ошибки (0.9), лимиты/хранение (0.10), изменение фактов (0.11), детали категорий (0.12) и итоговая схема (0.13) остаются отдельными решениями. Отдельный ручной ввод в FinanceIQ не утверждается импортом ручного журнала другого приложения.

### Основание для правил даты

Пользователь подтвердил совпадение даты внесения и дня движения денег. Профиль закрепляет локальный пользовательский день occurred_on DATE без сдвига через UTC. Переименованы ссылки даты в документации модели; полная сверка физических полей и ограничений остается в 0.13. Банковское проведение этой датой не подтверждается.

Сопоставление с опорным остатком и подтверждение полноты по D-06 остаются отдельными действиями. Даже запись в тот же день не доказывает совпадения с банковской датой проведения: это особенно важно у границы дня банковской выписки. Остатки и прогноз нельзя объявлять доступными по одному факту загрузки книги.

Календарь источника — Europe/Saratov (UTC+4). Проверка будущих дат использует «сегодня» в этой зоне; пользовательская зона прогноза остается отдельным параметром. Числовые даты Excel, системы дат книги и отсутствие UTC-сдвига приняты в [полном профиле](IMPORT_FORMAT.md).

### Согласованное сопоставление счетов

**Согласовано 2026-10-30:** книга принимается целиком. Перед Confirm пользователь явно сопоставляет каждое используемое название счета Money Manager с существующим собственным счетом FinanceIQ. Счета автоматически не создаются, строки других счетов не исчезают из preview. Для перевода нужны сопоставление обоих счетов и отдельное явное подтверждение по D-04.

Одна книга образует один batch с общим preview и атомарным Confirm по всем сопоставленным счетам. Backend проверяет владельца каждого целевого счета; совпадение названия не доказывает принадлежность. Изменение сопоставления должно отражаться в новом предварительном результате до подтверждения. Детали версий/digest и повторов остаются в 0.8; политика ошибок — в 0.9. Прежний односчетный проект таблиц требует сверки в 0.13.

При реализации нужно проверить сценарии: книга с двумя собственными счетами дает один общий результат; чужой целевой счет не проходит серверную проверку; одноименное название не заменяет сопоставление; изменение сопоставления делает прежний preview неактуальным; сбой записи одного счета откатывает всю книгу. Это критерии будущей проверки, тесты приложения сейчас не запускались.

### Согласованное представление возврата

**Согласовано 2026-10-30 для импортируемых данных:** исходная покупка сохраняется, возврат добавляется отдельной записью на дату движения денег. Это уточняет подготовку Money Manager к ранее принятой модели D-05; исходный доход/расход не уменьшается задним числом.

Ранее пользователь учитывал возврат изменением старой записи. Из такой выгрузки нельзя достоверно получить прежнюю сумму и дату отдельного поступления. Повторный экспорт измененной записи также не доказывает, что произошел возврат: без ID это может быть исправление, иная операция или неполная история. Автоматическое обновление уже импортированных финансовых фактов либо создание возврата по разнице сумм не согласованы; соответствующие решения остаются в 0.8/0.11.

Возврат покупки — отдельное поступление на листе Доходы, возврат дохода — отдельное списание на листе Расходы. Экономический тип refund, подтверждение/связь и категория следуют D-05 и принятому [профилю](IMPORT_FORMAT.md); метка источника не создает категорию FinanceIQ автоматически.

Синтетический пример отдельного движения возврата:

| Лист | Дата | Сумма в валюте счета | Смысл |
| --- | --- | --- | --- |
| Расходы | 2026-10-01 | 1000.00 RUB | Исходная покупка остается без изменения |
| Доходы | 2026-10-05 | 300.00 RUB | Частичный возврат — отдельное движение, подтверждаемое как refund |

Сохранение оригинала и отдельный возврат согласованы. История, уже потерянная при редактировании, не восстанавливается вымышленными записями. Границы исправления источника и повторного импорта остаются открытыми; решение 0.7 не подменяет решения 0.8/0.11.

## 4. Границы текущего разбора

Проверены состав листов, точные заголовки, типы ячеек, заполненность необязательных колонок, направления исходных величин и наличие формул. Исходная книга не изменялась и в репозиторий не копировалась.

Импортер, миграции и тесты приложения не создавались и не запускались. Профиль и синтетический образец приняты, проверки описаны в [IMPORT_FORMAT.md](IMPORT_FORMAT.md), §9. Пункт 0.7 завершен; решения 0.8–0.13 остаются отдельными задачами.
