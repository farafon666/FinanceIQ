# FinanceIQ — матрица финансовых инвариантов

**Статус:** матрица инвариантов и механизмы их проверки согласованы пользователем 2026-11-02 в пакете 0.13. Бизнес-основания приняты в D-01–D-10/D-13. Сценарии относятся к будущим тестам; реализация и запуск ими не подтверждаются. Открытые детали D-11/D-12 не утверждаются.

Для каждого правила указаны проверка сервиса, защита БД и наблюдаемый сценарий. `C-xx` — механизм из [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md), §8.2; `T-xx` — сценарий [DOMAIN_MODEL.md](DOMAIN_MODEL.md), §12; `CAT-xx` — [CATEGORIES.md](CATEGORIES.md), §8; `S-xx` — дополнительные сценарии ниже. Профильные сценарии импорта и жизненного цикла остаются в своих документах; матрица их не заменяет.

**Ни один сценарий здесь не является выполненным тестом приложения.** Если правило относится к входным данным, человеческому решению или вычисляемому результату, отсутствие универсального SQL-ограничения указано прямо. Защита БД не подменяется фразой «проверить в Python» там, где требуется межстрочная целостность.

## 2. Дополнительные сценарии сверки схемы

Все данные синтетические. Проверки значимых межстрочных условий выполняются на PostgreSQL, включая прямой некорректный DML и независимые DB-сессии; API-проверки изоляции дополняют FK, не заменяются ими.

| ID | Действие и ожидаемый результат |
| --- | --- |
| S-01 | Принять книгу на двух счетах с полной строкой перевода; у строки два движения с разными result_transaction_id. Попытка сослаться на mapping/row другой попытки запрещена. Ошибка последней стороны или скрытой записи откатывает все insert/link/действия/отзывы |
| S-02 | Две одинаковые покупки и один действующий факт: link+insert создают ровно один новый факт. Два link или insert+link к одному новому факту в одной попытке запрещены; другой принятый batch может иметь link к прежнему факту |

| S-04 | Две сессии: подтверждение полноты и новый факт внутри диапазона. Если подтверждение первое, импорт отзывает его; если импорт первый, старый план подтверждения отклоняется. Повторить для исключения факта, пустого интервала и нескольких пересечений. Категория/тип не меняют состав и не отзывают полноту |
| S-05 | Подтвердить перевод/несвязанный refund без отдельного согласия, с чужим/измененным фактом или устаревшим digest — отказ. При изменении правил, меняющем категорию/происхождение, нужен новый preview; нерелевантное правило не меняет план. SQL без требуемого action/item откатывается |
| S-06 | Снять полную пару: обе стороны unclassified в одном commit, прежняя версия связи/согласия сохранена. Снять refund-связь: unclassified, дальнейший unlinked refund требует нового согласия; нельзя обойти известный лимит. Прямая смена исходной суммы/DELETE/редактирование отмененного факта запрещены |
| S-07 | Отменить принятие, у которого все факты/связи внутренние: исключен ровно набор insert, все затронутые интервалы отозваны целиком с причиной; link, опоры и старые отзывы сохранены. Ошибка последнего исключения откатывает все действие. Повтор не создает новую отмену/отзыв |
| S-08 | Внешний действующий link или refund/transfer в любом направлении блокирует отмену. Еще действующая связь, созданная Confirm между двумя прежними фактами, тоже блокирует отмену даже у all-link; смена категории не стирает ее происхождение. После отдельного снятия ошибочной связи/отмены внешнего наблюдения проверка повторяется. All-link без изменения связей отменяется с нулем исключений |
| S-09 | Истечение ровно now=expires_at во время ожидания корня запрещает непринятый Confirm. Принятие, прошедшее проверку до срока, может commit после него; очистка не удаляет результат. Через сутки тот же accepted digest возвращает его и отметку отмены, иной digest конфликтует |

Очистка непринятой новой попытки не затрагивает принятое A, его отмену, нормализованные реквизиты/доказательства; после очистки те же байты требуют нового полного разбора |
