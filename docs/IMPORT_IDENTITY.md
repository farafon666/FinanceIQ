# FinanceIQ — идентичность и повторы Money Manager XLSX

**Статус:** согласовано пользователем 2026-11-01; пункт 0.8 / D-08 завершен как задача проектирования.

**Дата:** 2026-11-01.

Документ дополняет согласованный [профиль money_manager_xlsx_v1](IMPORT_FORMAT.md). Пользователь принял разделы 1–6 как пакет правил 0.8, а раздел 7 — как критерии будущей проверки. Обработка ошибочных записей отдельно согласована 2026-11-01 в [IMPORT_ERRORS.md](IMPORT_ERRORS.md), лимиты и хранение — в [IMPORT_LIMITS.md](IMPORT_LIMITS.md); пункты 0.9–0.10 завершены как задачи проектирования. Позднее в 0.11 принят жизненный цикл фактов по [FACT_LIFECYCLE.md](FACT_LIFECYCLE.md), включая отмену и явную новую попытку после нее. Импортер не реализован; итоговая схема (0.13) остается отдельной задачей.

## 1. Что можно установить без ID источника

У операции Money Manager нет устойчивого ID. Координата `лист + строка + сторона перевода` указывает на запись конкретной книги, но меняется при перестановке строк. Одинаковые дата, сумма, описание и даже все исходные поля могут относиться к двум разным покупкам.

Различаются:

- **Финансовый факт:** собственный ID операции FinanceIQ, присвоенный при ее создании.
- **Наблюдение источника:** запись конкретной книги и ее движение; у перевода два движения с отдельными результатами.
- **Повтор файла:** те же исходные байты того же источника у того же пользователя.
- **Кандидат на повтор движения:** похожий существующий факт, который пользователь может явно выбрать для связи.

Ни fingerprint, ни совпадение полного набора полей не становятся глобальным ID операции. UNIQUE по дате/сумме/описанию запрещен. Автоматического связывания без ID и автоматического схлопывания одинаковых покупок нет.

## 2. Повтор файла и область книги

Ключ книги: `(user_id, source_code, file_sha256)`, где `source_code = money_manager`, а `file_sha256 = SHA-256` исходных байтов XLSX до разбора. Ключ охватывает книгу целиком, без `account_id`. Профиль `format_code = money_manager_xlsx_v1` сохраняется как реквизит batch.

В ключ не входят имя файла, название отчета, сопоставления счетов, версия парсера, версия fingerprint или оформления preview. Смена этих параметров не дает права повторно провести те же байты. Пользователь берется из серверной сессии; другой пользователь имеет независимую область и не узнает о чужой книге.

- Подтвержденная книга возвращает тот же batch и сохраненный результат без новых операций и без повторного применения категорий или связей. Потерянный ответ после COMMIT не создает новый импорт.
- Неподтвержденная книга возвращает тот же batch. Изменение сопоставления счетов требует нового preview в этом batch; устаревшее подтверждение не применяется. Повторная проверка после ошибки или временного сбоя согласована в 0.9; хранение и восстановление истекшего preview отдельно приняты в 0.10 по [IMPORT_LIMITS.md](IMPORT_LIMITS.md).
- После Confirm сопоставление не переоткрывается обычной повторной загрузкой. Ошибочный выбор счета исправляется через допустимую отмену всего принятого результата и явную новую попытку по [FACT_LIFECYCLE.md](FACT_LIFECYCLE.md), §3–5, согласованным в 0.11 / D-13.
- Пересохранение XLSX, перестановка строк или изменение оформления могут изменить байты. Тогда создается другой batch, а защита от повторов выполняется на уровне движений по разделам 3–5.

Доказательство подтвержденного импорта и его результат должны оставаться доступными для проверки повторов. По отдельно принятому D-09 / 0.10 они хранятся, пока существует учетная запись; срок preview не разрешает повторное проведение. После очистки неподтвержденного содержимого сохраняется минимальная идентичность batch. Повтор тех же байтов после истечения требует полного разбора с новой версией/digest без автоматического применения старых решений по [IMPORT_LIMITS.md](IMPORT_LIMITS.md).

**Дополнение D-13 / 0.11:** отмена не меняет ключ книги и прежние принятые результаты. Обычный повтор файла/старого Confirm возвращает свой сохраненный результат с отметкой отмены, без восстановления фактов. После отмены пользователь может явно начать новую попытку с повторной загрузкой и полным новым планом/результатом в том же batch; прежние запросы не адресуют новую попытку. На книгу допускается одна текущая неподтвержденная попытка; действующий принятый результат сначала отменяется. Полный контракт и критерии — в FACT_LIFECYCLE.md, §5 и §8.

## 3. Поля и fingerprint кандидата

После валидации профиля и явного сопоставления счетов каждому движению вычисляется неуникальный fingerprint версии `money_manager_match_v1`:

```text
SHA-256(UTF-8(compact_JSON([
  "money_manager_match_v1",
  "money_manager",
  account_id,
  occurred_on,
  signed_amount,
  "RUB",
  source_comment
])))
```

Это JSON-массив с фиксированным порядком, без пробелов между элементами, без BOM и завершающего перевода строки. Не-ASCII символы записываются непосредственно в UTF-8, обязательные JSON-экранирования сохраняются; `/` не экранируется. Структурное кодирование не допускает коллизий от простой склейки полей.

| Поле | Согласованное представление |
| --- | --- |
| `account_id` | ID явно выбранного собственного счета FinanceIQ; UUID в нижнем регистре с дефисами. Исходное название счета ID не заменяет |
| `occurred_on` | Локальная календарная дата по профилю в ISO-формате `YYYY-MM-DD`; время записи не входит в fingerprint |
| `signed_amount` | Строка точного Decimal с двумя знаками после точки, без разделителей тысяч и без `+`; например, `-200.25` или `300.00`. Проверка D-01 предшествует вычислению; округления нет |
| `source_comment` | Комментарий источника, а не изменяемое описание существующей операции. Пустая ячейка и пустая строка дают `""`. Регистр, пробелы, переносы строк и Unicode-последовательности сохраняются без trim, casefold или Unicode-нормализации |

Не входят: координата строки, порядок листов, оформление, заголовок отчета, исходное название счета после сопоставления, исходные категория и теги, необязательная дублирующая RUB-пара суммы/валюты, внутридневное время, экономический тип и категория FinanceIQ, связи refund/transfer. Эти реквизиты сохраняются в происхождении согласно профилю и показываются при сравнении, но не доказывают новую операцию.

Изменение исходной категории или тегов оставляет тот же fingerprint. Изменение комментария меняет fingerprint, но не исключает поиск похожих движений. Перенос записи между листами также не служит доказательством тождества или нового факта; сравниваются подписанная сумма и прочие исходные реквизиты, а экономический смысл подтверждается отдельно.

Версия алгоритма сохраняется вместе с нормализованным наблюдением. Смена версии не разрешает заново импортировать прежние факты: сравнение должно оставаться возможным по сохраненным полям, включая наблюдения прежней версии. Ни hash, ни совпадение его байтов не заменяют сравнение полей.

## 4. Поиск и явный выбор

Поиск ограничен аутентифицированным пользователем и конкретным сопоставленным счетом. Основной набор кандидатов — существующие подтвержденные операции с той же `occurred_on`, подписанной суммой и валютой. В нем выделяются совпадения fingerprint, проверенные сравнением полей. Остальные показываются как похожие записи, например с другим комментарием. Допусков по сумме и угадывания соседних дат нет.

Для сравнения используются исходные наблюдения подтвержденных импортов Money Manager, связанные с действующим финансовым фактом. Несколько наблюдений одного факта дают одного кандидата с доступной историей происхождения. Поиск не расширяется на другие целевые счета. По D-13 ручного ввода фактических операций нет; отмененный факт не кандидат для link. Отмененные совпадения показываются отдельно как история и требуют явного insert, даже если действующих кандидатов нет.

| Ситуация | Действие preview |
| --- | --- |
| Нет кандидатов и похожих движений внутри книги | Предложить `insert`; общий Confirm принимает это предложение |
| Есть хотя бы один кандидат, включая полное совпадение | Оставить выбор `pending`, показать существующие факты и потребовать явный `insert` или `link` |
| Внутри книги несколько движений с одинаковыми счетом, датой, суммой и валютой | Показать группу и потребовать явного решения для каждого движения; автоматически не удалять и не объединять |
| Пользователь выбирает `insert` при наличии кандидата | Показать, что появится дополнительная операция; сохранить явное подтверждение, после Confirm создать отдельный факт |
| Пользователь выбирает `link` | Показать выбранный факт и различия источника; после Confirm сохранить происхождение без нового денежного движения |

`link` допустим только к существующему подтвержденному факту того же пользователя и счета с равными датой, подписанной суммой и валютой. Различия комментария, категории, тегов, времени или исходного названия счета видны и требуют явного подтверждения связи; оба наблюдения сохраняются. Это подтверждение пользователя о том, что запись относится к тому же движению, а не автоматическое доказательство.

Связь не переписывает дату, сумму, описание, экономический тип, категорию или существующие связи выбранной операции. Обновление факта по измененной выгрузке не входит в `link`. Отдельные действия D-04/D-05 не подменяются этим выбором.

В пределах одного принимаемого результата книги (попытки по D-13) существующий факт может быть результатом `link` не более одного раза. Отмененные результаты прежних попыток в этот счетчик не входят. Для двух одинаковых строк и одного существующего факта пользователь может связать одну строку и явно добавить другую; порядок строк не выбирает это за него. При двух существующих покупках доступны два разных кандидата. Между разными книгами повторные ссылки на тот же факт допустимы и не размножают кандидатов.

Связывание двух строк одной попытки книги с одним новым или существующим фактом, пропуск строк и автоматический выбор количества по формуле `max(число в файле, число в истории)` не вводятся. В 0.9 согласовано: ошибочные исходные строки исправляются в Money Manager с повторной загрузкой, без редактирования ячеек и пропуска в preview. Пока выбор совпадений не завершен, Confirm не создает финансовых фактов.

## 5. Переводы, возвраты и измененная история

Для полной строки перевода два движения проверяются отдельно в области своих сопоставленных счетов, с признаками исходящей/входящей стороны в происхождении. На каждой стороне сохраняется результат `insert` либо `link`; повтор одной стороны не разрешает второй раз создать ее сумму.

Дедупликация не подтверждает собственный перевод. Новая пара или дополнение ранее известной одиночной стороны требуют отдельного явного действия и проверок D-04. Если обе стороны связаны с уже существующей полной парой, повтор не создает новую связь. Нельзя присоединить движение, уже занятое другой парой, или скрыто изменить тип существующего факта ради импорта. Несовместимый выбор требует пересмотра preview. Неравные суммы обрабатываются по согласованному профилю без придуманной комиссии.

Возврат — отдельное движение с собственной датой и суммой. Его повтор обрабатывается так же, как повтор любого движения; `link` к исходной покупке с иной суммой/датой недопустим. Признак возврата и связь с оригиналом устанавливаются отдельно по D-05. Повторный импорт не меняет существующую связь и не увеличивает сумму возвратов.

Без ID нельзя надежно обнаружить редактирование даты, суммы или счета исходной записи. Такая строка может не иметь кандидатов и выглядеть как новая. В preview нужно явно пояснить: загрузка измененной истории не синхронизирует и не исправляет старые операции; перед Confirm пользователь сверяет новые движения. Изменение комментария ловится расширенным поиском раздела 4, но не дает гарантии тождества.

Отсутствие прежней строки в новом файле не означает отмену операции. Старые факты не удаляются; разница сумм не превращается в refund, комиссию или корректировку. Явная отмена всей книги и исправления приняты в 0.11 / D-13 по [FACT_LIFECYCLE.md](FACT_LIFECYCLE.md). Если один реальный счет создан в FinanceIQ дважды, автоматическая защита между этими объектами не обещается; риск показывается при сопоставлении.

## 6. Confirm и конкуренция

Подтверждение относится к конкретной версии preview и его серверному digest. В подтверждаемый план входят содержимое исходных движений, сопоставления счетов, решения `insert/link`, выбранные ID, показанные кандидаты, предлагаемые типы/категории и отдельные подтверждения D-04/D-05. Клиентский hash не заменяет серверной проверки.

В одной DB-транзакции сервис блокирует batch и все затронутые счета в стабильном порядке, повторно проверяет владельца, актуальность кандидатов/выбранных фактов, решения и финансовые ограничения. Изменение сопоставления, финансово значимого состояния выбранного факта или набора кандидатов требует обновить preview; новые решения за пользователя не принимаются. При двух параллельных импортах сначала завершившийся меняет набор кандидатов второго, поэтому второй не проводит прежний план без проверки и нового подтверждения.

Новые операции, результаты всех движений, согласованные связи, отзыв полноты по D-06 и итог batch записываются атомарно. `link` без нового факта не отзывает полноту. Ошибка откатывает всю книгу.

Повтор Confirm подтвержденного batch с тем же digest возвращает сохраненный результат; другой digest дает конфликт. Повторная загрузка тех же байтов возвращает результат по разделу 2. Изменение правил или версий парсера не меняет уже подтвержденный результат.

Точные поля, индексы, состояния, FK, ограничения однократного использования результата внутри книги и порядок блокировок сверяются в 0.13. Согласование 0.8 не утверждает прежние односчетные таблицы, банковский ID или ограничение «одна исходная строка — один факт».

## 7. Критерии приемки будущей реализации

Все данные в примерах вымышлены. Критерии приняты пользователем 2026-11-01; это ожидаемое поведение для будущих тестов, а не отчет об их запуске.

| Сценарий | Согласованный ожидаемый результат |
| --- | --- |
| Тот же XLSX под другим именем, с другим парсером или после потери ответа | Тот же batch и прежний результат; новых движений нет |
| Те же байты, но другое сопоставление после Confirm | Повтор не переоткрывает сопоставление и не проводит книгу еще раз |
| Два пользователя загружают одинаковые байты | Независимые batch и результаты без раскрытия чужих данных |
| Книгу пересохранили, переставили строки/листы или изменили оформление | Возможен другой file hash; существующие движения показаны кандидатами, автоматического добавления повторов нет |
| Две одинаковые покупки `-100.00` в один день без существующей истории | Две видимые записи; явные два `insert` создают два факта |
| Две одинаковые строки и один существующий факт | Выбор `link` + `insert` дает всего два факта; два `link` к одному ID недопустимы |
| Одна строка и два существующих одинаковых факта | Два кандидата; пользователь выбирает один ID или явно создает третий факт |
| Операция наблюдалась в трех подтвержденных книгах | В следующем preview один кандидат по ID факта, а не три копии |
| Изменены исходные категория/теги; FinanceIQ-категория назначена вручную | Fingerprint прежний; требуется выбор, `link` сохраняет ручную категорию и оба наблюдения |
| Изменен комментарий, включая регистр/пробелы/перенос | Fingerprint другой; кандидат найден по счету, дате, сумме; различие видно, скрытой перезаписи нет |
| `1.230` вместо `1.23`; другая система дат Excel с тем же локальным днем | Одинаковые канонические поля и fingerprint после валидации |
| Время `00:00` заменено на `23:45` того же локального дня | День и fingerprint прежние; исходное время доступно в сравнении |
| Изменены сумма, дата или целевой счет; старая строка исчезла | Автоисправления/удаления/refund нет; ограничение распознавания показано пользователю |
| Совпал hash, но сравниваемые поля различны | Автоматической связи нет; hash не заменяет проверки полей |
| Повтор полной строки перевода, обе стороны уже связаны | Две ссылки на прежние движения, без новых сумм и новой пары |
| У перевода одна существующая сторона и одна новая | План сторон проверяется вместе с D-04; нет повторного списания и скрытого переподключения пары |
| Повтор строки возврата | Ссылка на прежний refund без повторного увеличения суммы возвратов |
| Чужой счет/кандидат в подмененном запросе | Отказ серверной проверки без раскрытия чужих данных |
| Между preview и Confirm появился кандидат или изменился выбранный факт | Старый план не проводится; требуется актуальный preview и Confirm |
| Параллельные Confirm одной книги / двух пересекающихся книг | Одна запись результата batch / повторная проверка кандидатов второго импорта под блокировками |
| Ошибка на последней стороне перевода или последнем счете | Откат всей книги, включая новые факты и отзыв полноты |
